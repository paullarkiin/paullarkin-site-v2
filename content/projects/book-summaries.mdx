### Overview

Summaries is a personal side project exploring how AI can make discovering books faster and more accessible.

The idea came from my own reading habits. When browsing bookstores, I often find interesting books but don't always know if they are worth buying. I wanted a simple way to quickly understand what a book was about, save interesting titles and write inital thoughts that I could come back too.

### Why I Built It

At the time, I had recently completing a React course, Having the idea floating around it gave me a good chance to apply what I had learned by building something practical for myself.

Inspiration came from services like Blinkist and other short-form reading platforms that I had previously used but I wanted a simpler version focused on my own goals.

---

### How It Works

Practically it a minamistic looking frontend that puts the focus on the books.

This is done with a grid layout, supabase backend (which will be swapped out) and an API server that sends request to OpenAI complications API endpoint and returns structured JSON.

When the user saves a book they grid item with an inner page which contains the same information as the modal and along with the ability to add comments. Which has been added but not styled which is why it not shared here.

The whole experience is designed around a simple flow:

1. Find a book
2. Generate a summary
3. Decide whether to save it or skip it
4. Keep a personal collection of interesting reads

### Challenges

<h4 className="mt-8"> Prompt engineering </h4>

One of the interesting challenges was making AI output feel consistent.

Instead of simply displaying generated text, I looked into how to return structured content that I mentioned about. This was key to the user experence of the project. It took a few attempts but am now happy with the output. Below you can see the final code used on the API server.

The experimenting involved:

- Prompt structure
- Formatting requirements
- Handling inconsistent responses

```
openai
    .createChatCompletion({
      model: "gpt-4.1",
      messages: [
        {
          role: "system",
          content:
            "You are a helpful assistant that gives summarizes of books. Respond ONLY in JSON, no extra text.",
        },
        {
          role: "user",
          content: `
          Summarize the following book into this JSON format:
          {
            "title": "<book title>",
            "author": "<author name>",
            "short_summary": "1-2 lines max summary of the book",
            "summary": "<full summary>",
          }

          prompt text:
          ${text}
        `,
        },
      ],
      max_tokens: 1200,
      temperature: 0.3,
    })

```

<h4 className="mt-12"> Cover fallback </h4>

Another challenge to do with user experence of the project was fetching and handling book covers these API's are not very well documented if at all. They could accept and use different serch parameters to complete a cover look up. This impacts the ability to find the book cover.

To help improve the success rate of a book cover being found I would check the first as it had a better results at the time. If this failed it would fallback to the second and if nothing was found it would show the default placeholder.
